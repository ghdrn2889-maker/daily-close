# 당일 마감

수익 · 경비 · 소비 · 고정지출 네 축으로 하루를 마감하는 개인 현금흐름 앱.

서버 없이 브라우저 안에서만 동작하며, 기록은 사용하는 기기의 브라우저 저장소에 남습니다.
이 저장소에는 앱 코드만 있고 개인 기록은 들어 있지 않습니다.

## 네 축

| 종류 | 뜻 |
|---|---|
| 수익 | 벌어들인 돈 |
| 경비 | 벌기 위해 쓴 돈 |
| 소비 | 나를 위해 쓴 돈 |
| 고정지출 | 매달 자동으로 나가는 구독 |
| 저축 | 쓴 게 아니라 옮겨 둔 돈 |

경비와 소비를 가르는 기준은 하나입니다 — **이 지출이 없었으면 수익이 줄어드는가.**

저축은 잃은 돈은 아니지만 **지금 쓸 수 있는 돈도 아닙니다.** 손닿지 않는 곳으로
옮겨간 것이므로 남은 돈에서 뺍니다 — 순익 = 수익 − 경비 − 소비 − 고정지출 − 저축.
대신 얼마나 모았는지는 따로 셉니다. 이번 달 탭의 **모은 돈** 칸이 누적과 월평균을 보여주고,
브리핑에도 그 달 저축액과 누적이 함께 나옵니다.

### 모으는 곳

같은 저축이라도 성격이 다릅니다. 적금은 약속한 기간과 회차가 있고, 따로 빼두는 돈은
목표만 있거나 그것도 없습니다. 한 칸에 넣으면 "이번 달 적금을 넣었나" 를 영영 알 수 없습니다.

| 종류 | 적는 것 | 따라가는 것 |
|---|---|---|
| 금융상품 | 한 달 납부액 · 기간 · 시작 월 | 넣은 회차, 남은 회차, 마지막 납입월, 진행률 |
| 자유 저축 | 목표 금액 (선택) | 모은 금액, 목표까지 남은 금액 |

저축의 분류는 **저축처 하나로** 합니다. 항목과 저축처가 따로 있으면 "예금" 이라고만 적힌
기록이 어느 예금인지 끝내 알 수 없습니다. 그래서 저축에는 일반 항목 목록을 쓰지 않습니다.

저축을 기록할 때 저축처를 고르면 그쪽으로 쌓입니다(`txn.pot`). 저축처가 없으면 기록 시트에서
바로 만들 수 있고, 만들고 나면 적던 금액·메모를 그대로 들고 돌아옵니다.

안 고른 기록은 **지정 안 함** 으로 묶이고, 거기 **정리하기** 로 한꺼번에 옮깁니다 —
한 건씩 열어 고치게 두면 아무도 안 합니다. 저축처를 지워도 넣은 기록은 지우지 않고
연결만 끊습니다.

금융상품은 이번 달 납입이 아직이면 브리핑이 알려줍니다 — 적금은 거르면 손해가 나므로.

예금을 깨서 돌아온 돈도 같은 이유로 수익이 아닙니다. 가져오기에서 자동으로 제외되며,
그때 넣어 둔 저축 기록을 지우는 것이 맞는 처리입니다.

## 파일

| 경로 | 용도 |
|---|---|
| `prototype.html` | **원본.** 아티팩트용 body 조각 (doctype 없음) |
| `당일마감.html` | 단독 실행본. 더블클릭하면 브라우저에서 바로 열림 |
| `docs/` | 배포본. GitHub Pages가 이 폴더를 서비스 |
| `build-standalone.js` | 원본에서 위 두 배포본을 생성 |
| `gen-icons.js` | 앱 아이콘 PNG 생성 (크롬으로 렌더) |

## 빌드

```bash
node build-standalone.js     # 당일마감.html + docs/index.html 갱신
node gen-icons.js            # 아이콘 다시 생성 (필요할 때만)
```

`prototype.html` 만 고치고 빌드하면 나머지가 따라옵니다. `docs/sw.js` 의 캐시 버전도
앱 버전을 자동으로 따라가므로, 배포하면 이전 캐시가 정리됩니다.

## 데이터

기록은 `localStorage` 의 `daily-close-v3` 키에 저장됩니다.
**주소마다 저장소가 별개입니다** — 배포 주소, 로컬 파일, 아티팩트는 서로 데이터를 공유하지 않습니다.

백업은 설정 → 데이터 → 내보내기에서 JSON 파일로 받습니다. 형식은 고정되어 있습니다.

```json
{ "app": "daily-close", "schema": 1, "exportedAt": "...", "data": { "txns": [], "presets": [], "recurrings": [], "cats": {} } }
```

가져오기는 이미 있는 기록을 건드리지 않고 없는 것만 추가하므로, 같은 파일을 여러 번 넣어도 중복되지 않습니다.

## 구독 · 고정지출

이번 달 탭에 **결제일 순으로** 늘어놓습니다. 설정 안 목록만으로는
"이번 달 뭐가 언제 빠지나" 를 알 수 없고, 결제일은 돈이 나가기 전에 보여야 쓸모가 있습니다.

```
구독 · 고정지출                              [추가]
 5일  넷플릭스     소비        17,000    2일 뒤
12일  Claude 구독  경비        30,000    9일 뒤
20일  자동차 보험  경비·매년   780,000   17일 뒤
25일  통신비       소비        55,000    22일 뒤
30일  헬스장       소비        60,000    27일 뒤
────────────────────────────────────────────
이번 달 청구                          942,000원
아직 남은 결제                        942,000원
하루당  연환산 ÷ 365                    7,463원
```

지난 결제는 흐리게 `결제됨`, 오늘 빠지는 것은 빨갛게 `오늘`. 줄을 누르면 바로 수정됩니다.
달력에도 결제일에 테두리가 생깁니다.

- **매달**: 그 달 결제일. 31일 결제가 2월이면 말일로 당깁니다
- **매년**: 해당 월에만 나타납니다
- 끈 구독(`active:false`)은 목록에 안 나옵니다. 다만 전부 꺼져 있으면 그렇다고 말해줍니다

구독이 하나도 없어도 **카드는 그대로 있고** 안내와 `첫 구독 등록하기` 가 뜹니다.
만들 자리는 비어 있을 때 가장 필요한데, 예전에는 그때 카드를 통째로 숨겨서
만들 버튼까지 같이 사라졌습니다.

오늘 빠지는 구독이 있으면 **오늘 탭 위쪽에** 한 줄로 알려줍니다 — 결제일은 그날 알아야 합니다.

`이번 달 청구` 는 그 달 실제 청구액이고, `하루당` 은 연환산 ÷ 365 입니다 — 달마다 숫자가
흔들리지 않게 하려는 것이라 하루 화면의 고정지출은 늘 이 일할액을 씁니다.

## 이 달 정리해서 내보내기

이번 달 탭 맨 아래. 종이로 남기는 것과 화면으로 보는 것은 목적이 다릅니다.
화면은 훑는 용도라 카드로 나누지만, 종이는 한 장에 다 들어와야 합니다.

| | 내용 |
|---|---|
| **인쇄 · PDF** | `window.print()` + `@media print`. 라이브러리를 쓰지 않으므로 CSP 제약이 없고, 한글 글꼴도 브라우저 것을 그대로 씁니다 |
| **CSV** | 요약 · 날마다 집계 · 상세 내역 세 블록. `당일마감-YYYY-MM.csv` |

먼저 **미리보기**로 보여주고, 저장을 누를 때 `document.title` 을 `당일마감-YYYY-MM` 으로
바꿉니다 — 크롬은 PDF 파일명을 여기서 가져옵니다. 인쇄가 끝나면(`afterprint`) 제목을
되돌리고 미리보기를 닫습니다. 기기별로 PDF 고르는 곳이 달라 안내 문구도 갈라 놓았습니다.

### 날마다

하루씩 마감하는 앱이니 종이도 하루씩 떨어져야 합니다. 거래를 죽 늘어놓으면
"그날 얼마 남았나" 를 종이 위에서 다시 더해야 합니다.

```
날짜      수익      경비        소비      저축       일계
1(토)  195,000  −14,000    −4,500            +176,500
14(금)                 −1,250,000          −1,250,000
25(화)  195,000  −14,000    −4,500  −500,000  −323,500
────────────────────────────────────────────────────
합계  2,340,000 −168,000 −1,456,000 −500,000  +216,000
고정지출                                       −17,000
남은 돈                                       +199,000
```

상세 내역(건별)은 그 아래에 따로 붙습니다. 고정지출은 등록된 구독에서 계산한 값이라
상세 목록에 없습니다 — 보고서 아래에 그렇게 적습니다.

## 소비 패턴

**패턴** 탭. 자기 기록을 읽는 일은 통계라 서버도 열쇠도 없이 계산으로 돕니다.

| 보는 것 | 방법 |
|---|---|
| 평소 얼마나 | 한 달 합계 평균 · 쓴 날 하루 · 한 번 |
| 일한 날과 쉰 날 | 수익이 있는 날을 근무일로 보고 소비를 비교 |
| 요일 | 요일별 하루 소비 |
| 어디에 쓰나 | 항목별 합계와 비중 |
| 작지만 자주 | 건당 2만원 이하가 몇 번 쌓여 얼마가 됐는지 |
| 구독일 수 있어요 | 3개월 이상 연속 · 달마다 한 번꼴 · 금액 편차 25% 이내 |
| 큰 지출 · 달마다 | 상위 5건, 월별 추세 |

**습관을 볼 때는 평균을 쓰지 않습니다.** 노트북 한 번 산 게 금요일이면 "금요일에 23만원씩
쓴다" 가 되어버립니다. 요일·근무일 비교는 전부 중앙값입니다. 큰 지출은 따로 보여줍니다.

소비 기록이 5건 미만이면 아무 말도 하지 않습니다.

### 키워드로 묶어보기

항목 이름이 제각각이면 같은 습관이 흩어집니다. 메가커피·스타벅스·이디야는 사람 눈에는
다 커피입니다. 이름을 통일하라고 하는 대신 **키워드로 걷어 담습니다.**

항목과 메모에서 대소문자 없이 찾고, 쉼표로 여러 개를 넣습니다 (`커피, 스타벅스, 이디야`).
합계 · 횟수 · 건당 · 한 달 · 소비 대비 비중 · 달별 추이 · 어느 항목에서 왔는지를 보여줍니다.
소비와 경비를 함께 찾으므로 `주유` 같은 키워드도 됩니다 — 전부 경비면 그렇게 적습니다.

자주 보는 묶음은 저장해 두면 패턴 탭에 계속 나옵니다(`state.tags`). 백업에도 실립니다.

## 캐디 앱 연동

읽기 전용 창구 하나만 봅니다. 계약은 세 필드가 전부입니다.

```
GET /api/work-income?from=YYYY-MM-DD&to=YYYY-MM-DD
Authorization: Bearer <열쇠>
-> [{ "date": "2026-08-21", "count": 1, "amount": 170000 }, ...]
```

날짜별 합산이고, 0원인 날은 오지 않습니다. 이 앱은 쓰기를 하지 않습니다.

**열쇠는 저장소에 넣지 않습니다.** 사용자가 캐디 앱에서 발급해 화면에서 붙여넣고,
`state` 와 분리된 `caddieKey` 항목에만 둡니다. 그래서 백업 JSON 에도 실리지 않습니다.

동기화는 앱을 열 때 조용히 한 번(1시간 간격), 그리고 설정에서 수동으로 돌립니다.
받아온 구간은 그대로 맞춥니다 — 새 날짜는 추가, 바뀐 날은 갱신, 취소된 날은 삭제.
`ext:'caddie'` 표시가 없는 기록(직접 입력)은 절대 건드리지 않습니다.

### 서버 주소는 앱에서 바꿉니다

기본 주소는 코드에 있지만, 설정 → 캐디 앱 연동 → **서버 주소 · 바꾸기** 로 덮어쓸 수 있습니다.
`https://` 만 받고, 값은 `caddieApi` 항목에 열쇠와 마찬가지로 `state` 와 분리해 둡니다.
비워서 저장하면 기본 주소로 돌아갑니다.

주소가 바뀌는 이유는 하나입니다 — **브라우저는 공개 사이트가 사설망 주소로 요청하는 것을 막습니다.**
`*.ts.net` 은 A 레코드가 `100.x` (CGNAT 사설 대역) 라서 크롬이
`ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS` 로 차단합니다. 앱 쪽에서 우회할 방법은 없고,
캐디 앱이 공인 IP로 해석되는 주소를 내주어야 합니다. 그 주소를 받으면 여기에 붙여넣으면 됩니다.
